# Requirements Glossary

This document defines key terms used in the requirements documentation.

## Glossary Terms

**Requirement**: A specification of what a system should do or a property it should have.

**Traceability**: The ability to trace requirements to their implementation and verification.

**Verification**: The process of ensuring that a requirement has been correctly implemented.

**Validation**: The process of ensuring that a requirement meets the intended use case.

**ISO 29148**: International standard for requirements engineering.

**TBD**: To Be Determined - placeholder for information that will be specified later.

**TBR**: To Be Reviewed - placeholder for information that needs review.

**RTM**: Requirements Traceability Matrix - a document linking requirements to their implementation and tests.

**Priority**: The relative importance of a requirement (e.g., High, Medium, Low).

**Status**: The current state of a requirement (e.g., Planned, Proposed, Accepted, Implemented).

**Owner**: The individual or team responsible for a requirement.

**Stakeholder**: Any person or group with an interest in the requirements.
